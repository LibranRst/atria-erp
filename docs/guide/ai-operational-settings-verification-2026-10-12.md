# AI operational Settings verification — 12 October 2026

## Implemented workflow

The existing FINANCE_INPUT family now supports `APPROVAL_THRESHOLDS` and `EXPENSE_CATEGORY_SETTINGS`, alongside invoices, schedules and complete company budget defaults. New read-only tools return actual tenant thresholds and category/default references; one-character category search returns human choices and stable20-row pagination. Proposal tools accept strict partial patches and a supplied reason. Omitted values remain intact; explicit null clears a category description. Prose agreement never writes; the human presses the reviewed action or protected confirmation.

Settings reads require AI access and view:settings. Threshold/category mutation requires its actual management grant, and category ratio changes additionally require manage:budget_settings. Company rights are independent of project dataScope. Canonical5 category IDs/codes remain fixed and active; non-core availability changes retain history. Default usage and multi-category/cap rebalancing remain in the existing full-default workflow.

Manual Settings actions and AI confirmation use the same tenant-scoped transactional writers. Approval thresholds store integer cents and preserve fractional rupiah when evaluating field costs. Zero explicitly means all eligible submissions need Owner approval. Existing submitted Owner decisions and over-budget safeguards remain unchanged; only future evaluations use the new policy. Missing config uses disclosed seed/fallback; malformed config blocks AI preview and a complete explicit manual overwrite can repair it with original evidence. Category ratios update the authoritative active default allocation and compatibility reference together, preserve other shares/cap and reject enabled totals above100%. Metadata, status and ratio changes do not rewrite existing project budgets or monetary records. Locks, source fingerprints, ownership/tool-action identity, current rights, expiry and atomic audit/confirmation receipts prevent stale/repeated or conflicting writes. No migration was needed.
