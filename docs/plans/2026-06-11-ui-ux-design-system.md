# UI/UX & Design System Documentation Plan

**Goal:** Create comprehensive, production-grade UI/UX specifications and design system guidelines (in Bahasa Indonesia with English technical terms) for the mobile-first, finance-first Atria ERP application following the iOS 26 Solid design philosophy.

**Architecture:** Detailed markdown specifications describing the layout, screens, components, color tokens, typography, and interactive behaviors.

**Tech Stack:** Next.js, Tailwind CSS (for tokens mapping, though CSS is vanilla), Drizzle ORM schemas references, and Gemini AI.

---

### Task 1: Create MOBILE_FIRST_UI_UX.md

**Files:**

- Create: `docs/05-ui-ux/MOBILE_FIRST_UI_UX.md`

- [ ] **Step 1: Write introductory context & App Shell design**
      Define the mobile-first scope, target users (Owner, Admin, PM), and the sticky bottom navigation layout (Projects, Ledger, Add Expense, Profile) with touch targets >= 44x44px.

- [ ] **Step 2: Write Finance Dashboard screen specification**
      Detail the overview of bank accounts (BCA Operational, Mandiri Project, Petty Cash Office), critical financial alerts (INFO, WARNING, CRITICAL), and audit logs stream.

- [ ] **Step 3: Write Project Finance Detail screen specification**
      Detail the project list and detail screens, showcasing the project financial health status (HEALTHY, WARNING, CRITICAL), and actual spent vs allocated budget comparison.

- [ ] **Step 4: Write Client Payment Tracking screen specification**
      Detail client invoices, stages (DP, PROGRESS_1, PROGRESS_2, PELUNASAN, AD_HOC), progress milestones, and payment recording.

- [ ] **Step 5: Write Expense Input Form screen specification**
      Detail the PM field request form optimized for speed and one-handed usage, OCR integration flow using Gemini AI, and receipt uploading.

- [ ] **Step 6: Write Vendor Payable screen specification**
      Detail vendor bills, payables list, payment verification, and authorization flows.

- [ ] **Step 7: Write Owner Approval & Action screen specification**
      Detail the high-priority approval queue for over-budget items and transactions exceeding Rp 5.000.000.

- [ ] **Step 8: Write AI Briefing screen specification**
      Detail the daily executive summary generated by Gemini AI for the Owner, containing key financial metrics.

- [ ] **Step 9: Write UI states (Empty, Loading, Error) & swipe/tap interactions**
      Specify loading skeletons, error screens with retry buttons, empty state illustrations, and gestural interactions (swipe-to-approve, swipe-to-delete).

- [ ] **Step 10: Write Responsive Desktop Adaptation strategy**
      Outline how the mobile layout scales up to a dual-pane or desktop layout for Admins/Owners.

### Task 2: Create IOS26_SOLID_DESIGN_SYSTEM.md

**Files:**

- Create: `docs/05-ui-ux/IOS26_SOLID_DESIGN_SYSTEM.md`

- [ ] **Step 1: Write iOS 26 Solid Philosophy & Tone**
      Explain the aesthetic philosophy (solid colors, clear hierarchies, micro-borders, avoiding excessive blur/frosted glass/liquids).

- [ ] **Step 2: Define Color Tokens (HSL Palette)**
      Detail the precise HSL color codes for slate background, deep indigos primary, emerald success green, and amber warning/critical.

- [ ] **Step 3: Define Typography & Spacing**
      Specify Inter/Outfit font family scales, weights, and the 4px/8px modular grid spacing.

- [ ] **Step 4: Define Border Radii**
      Specify `rounded-lg` (8px), `rounded-2xl` (16px), and `rounded-t-3xl` (24px) use cases.

- [ ] **Step 5: Define Cards & Buttons Components**
      Detail the padding, border, shadow, hover states, and touch target rules (minimum 44x44px).

- [ ] **Step 6: Define Forms, Bottom Sheets, & Controls**
      Detail text inputs, label placements, bottom sheet drawers (with backdrop and pull bar), segmented controls, and list rows.

- [ ] **Step 7: Define Status Badges, Financial Numbers, & Micro-Charts**
      Specify color-coded badges, high-contrast currency rendering (Rupiah), progress bars, and sparklines.
