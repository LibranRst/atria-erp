# Home web parity and native controls

Confirmed through Grilling on 2 October 2026. The current web **mobile `/ledger`**, including all six tabs, is the content/layout/copy reference. Desktop `/admin` is not the mobile layout reference.

Later user steering replaced the stock segmented visual with the web composition, restored full labels/icons/counts, reduced shared button size and requested visible iOS 26 Liquid Glass in the bottom dock. The newer decisions and verification are recorded in `2026-10-02-mobile-controls-web-adaptation.md`; the short-label stock-control decisions below are historical.

## Agreed decisions

- Port the current content and visual hierarchy of Ringkasan, Persetujuan, Budget, Jatuh Tempo, Rekening and Material. Do not redesign other pages' content in this batch.
- Make shared buttons and segmented controls native app-wide. Buttons use contextual system styles (prominent, glass/bordered, plain, destructive) with Atria tint and native control fonts. Interactive rows/cards preserve their row/card composition through plain native action controls.
- Use six scrollable native segments, shorter labels where clear, and workload counts in the owning content/header rather than segment badges. Quick horizontal swipe scrolls; hold-and-slide previews selection locally; releasing commits one tab change. Cancellation preserves the initial tab. Holding at the strip edge scrolls slowly to expose other segments. Vertical reading position and explicit deep-link tab restoration remain stable.
- Match MoneyValue variants at current web callsites, primarily fullDynamic; retain compact values where the current web intentionally uses them.
- Read-only approval/proof/budget-impact, bank and exact transaction detail render natively. Approval decisions, account creation/edit/archive, manual money movement and transfers remain explicit browser workflows for now. No financial or inventory mutations during UI QA.
- Preserve the web's combined outstanding amount for seven-day document exposure; cash coverage uses payable obligations only. Apply this meaning correction consistently in web and mobile through a pure shared calculation.
- User steering after the storage increase: use the existing iOS 26.5 runtime for development. The newly downloaded iOS 27 runtime, its newly created simulator devices and the earlier task-specific DerivedData were removed at the user's explicit request. Do not download another runtime or create a large separate build cache without first explaining its storage cost and obtaining explicit authorization. iOS 27 interaction behavior remains deferred and unverified.
- The temporary QA build cache measured 3.3 GB on the external SSD. It and 26 MB of temporary exports were removed after installing the final client. Preview data, source, installed client, screenshots and environment restoration files are retained.

## Implementation ownership

1. Shared native segmented view/adapter: existing local Expo module + stock UIKit segmented control and horizontal scroll container. Public APIs only; keep system rendering/animations rather than a React imitation. Native gesture ownership separates scroll from scrub, supports cancellation/edge scrolling, respects Reduce Motion and accessibility.
2. Shared buttons/row action: @expo/ui native Button, platform-isolated where necessary, real loading/disabled/accessibility semantics, effective 48pt targets and native font/tint roles. Preserve existing used props rather than fabricating React Native press events. Split nested row/edit actions into siblings. Existing UIKit/SwiftUI header, menu and dock controls remain native.
3. Home compositions: align current web mobile hierarchy, summaries/status headers, compact preview rows versus detailed tab rows, margin/category comparisons, due timelines, approval priorities, account hierarchy and material budget context. Reuse/extend public shared SummarySurface, SummaryFact, MoneyValue, GroupedSurface and native row controls.
4. Read detail: native Stack form sheets using shared BottomSheet; approval data already in the shared screen DTO, bank data already loaded, exact cash ActivityDetail exposed through an explicit authorized read-only tRPC seam. Existing web signatures/contracts stay compatible; native never calls the private web-RPC bridge.
5. Shared cash summary/verification/integration: pure core calculation and meaningful regression coverage for mixed receivables/payables and zero obligations. No money movement logic, database schema, balances or seed reset changed.

## Delivered implementation

- All six Home tabs now follow the current web mobile content hierarchy. Ringkasan's native-only category list and extra budget grids were removed; project risk previews/detail rows, category indicators, document-first due timelines, approval priorities, account identity and material budget context use shared public primitives. Primary exact amounts use fullDynamic at corresponding web callsites; intentional compact secondary metrics remain.
- The Home strip uses Ringkas/Persetujuan/Budget/Tempo/Rekening/Material without badges. Workload counts belong to the owning summary/header. Shared native Button and RowAction preserve one action per row; the iOS segmented backend uses the local UIKit module. Implemented gestures require the runtime evidence below before being reported as verified.
- Approval context/proof/budget impact, account identity/recent transactions and the exact selected cash ActivityDetail have native read-only sheets. The cash detail query is an explicit Actor-authorized tRPC read. No native approval or bank mutation procedure was added.
- Bank browser destinations restore context: `bank-action=create` on the accounts tab, `account=<id>` for read-only detail, and `account=<id>&bank-action=edit|movement|transfer` for the permitted form. The web hook checks permissions/account availability, waits for an existing sheet's dismissal, then consumes only the bank-intent parameters with replace while retaining tab/surface/other query/hash. Unknown or denied intents fail closed; no intent auto-submits, archives or moves money.
- Cash document exposure remains combined hutang/piutang for the seven-day groups. Shared cash coverage uses payable obligations only; no payables yields “Tidak ada hutang”. The meaning is consistent in web and native.
- Shared material quantity presentation distinguishes RAP deficit, low-stock availability/minimum, waste quantity and adjustment quantity without inventing direction. Missing reversal quantities remain absent. Historical movement/reversal DTO stock placeholders are not displayed or announced as current physical inventory; their project/location and event quantity provide context.
- Native screen/UI caches are scoped by user, session, role, permissions and data scope. Changing scope cancels/removes the previous scoped cache; access revocation hides protected reads. Browser cookie authentication remains separate from native bearer authentication.

App typechecks, workspace lint, 34 mobile tests, focused cash/material/navigation/intent regressions, disposable native HTTP authorization coverage, iOS/Android exports and the final native build passed. iOS 26.5 QA verified six Home tabs, native read sheets/proof retry/expansion, representative shared buttons and four bank web intents without submitting mutations. Native quick-pan scrolling now changes only horizontal strip offset; tapping commits once. A public native UIPan owns horizontal strip scrolling because the stock control prevented the container's built-in pan. All temporary traces were removed before the final build.

All six tab compositions were checked at a temporary native content width of 320pt, and Material at 360/390pt, on the existing 402pt simulator; those bounds were removed after QA. This does not claim other device sizes, 430pt, Android runtime, large Dynamic Type or assistive-technology verification. Timed hold/slide/release/cancel and edge auto-scroll remain implemented but unverified because the available browser input compresses native touch duration. iOS 27 remains deferred. Full evidence and preview instructions are in `docs/guide/mobile-home-preview.md`.

## Reference findings

The pre-implementation review found that web hero/summaries used fullDynamic and richer shared surface headers, while native retained older compositions. Web mobile overview did not contain the full category section previously added to native. Web project rows had compact and detailed contracts, target/projection comparison and risk categories; due rows were timeline entries with document-primary hierarchy; recent cash opened exact activity. Native actions still relied on custom RN Pressable/Reanimated Button, and six scrollable/badged segments forced the React fallback. The delivered implementation above addresses these gaps.

Prior preview sandbox and local settings are retained. Core data/finance behavior, RBAC, scoping, API ownership and existing native chrome remain authoritative. No broader mutation port or rollout is implied by this batch.
