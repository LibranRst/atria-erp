# Live AI conversation acceptance

User-authorized live model testing in the visible Browser, from natural-language chat through real human confirmation and stored result. Use the existing configured NINEROUTER gateway/model and a named disposable database; never inject assistant tool outputs for this run.

## Scenarios

1. Current company margin/default policy comes from actual Settings, with no business writes.
2. Ambiguous warehouse/material and missing audit reason require clarification; no first-match selection or premature correction.
3. A fully clarified single stock correction produces exact before/after preview. Verbal approval alone does not post; human Save creates one movement/audit/receipt.
4. A multi-material correction uses shared batch review and one atomic confirmation. Saved history and reload must not double-post.
5. Excessive stock reduction is visibly blocked; a corrected valid request can recover with a fresh proposal.
6. Own-profile name correction tests another card family and actual session refresh, with an explicit Save and subsequent restoration.
7. Completed Quick Start is read accurately and cannot be reset or recreate the first project.
8. Ordinary project creation collects required client/manager/value information, uses Settings defaults and completes through the real card/wizard/save path if offered by the current grants.

## Evidence and repair boundary

Fixture operator may seed clearly named synthetic material/location/client/manager references and snapshot state; it must not author assistant responses, proposal parts or confirmation receipts. Chat messages and tool results are produced by actual Browser prompts and the configured live provider. Observer records provider/token metadata, chosen tools, confirmation IDs and exact before/after domain counts/hashes. No real cash payments, security-role changes or external communications are test targets.

Fix concrete failures found in the authorized path. Before substantive repairs, record reproduction/root cause and preserve a meaningful regression. Follow existing immutable proof, transactional, RBAC and shared UI contracts. Relevant gates and Browser retest accompany repairs. Report tested scenario/family boundaries honestly rather than claiming every registered action/model/role is certified.
