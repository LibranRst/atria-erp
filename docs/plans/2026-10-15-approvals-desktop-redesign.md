## Approved direction

The user approved the recommended desktop `/approvals` redesign: compact queue summary, native HeroUI tables with search, filters, full-result sorting and pagination, and contextual evidence/impact with the existing Setujui/Tolak actions. Inherit the established Dashboard, Settings and Expenses Atria Operate grammar: Manrope, cool canvas, white 16px panels, native 20px tables, compact capsule controls and semantic ink/terracotta. This is a precisely specified extension of the current visual system, not a replacement identity or open concept exercise.

Desktop >=1024px uses a compact queue band, peer type/risk views and inline search/project filters. At >=1280px list and independent detail sit beside each other; smaller desktop uses list/detail progression with Back. Existing mobile/native composition remains authoritative.

## Implemented result

The stable ApprovalList now owns the page header, pending Change Order notice, queue source and all existing decision/receipt overlays. Desktop uses four comparison facts, type/risk peer views, simultaneous search/project/priority controls and six native table columns. Explicit fixed column proportions keep the priority column visible at 1024/1280/1440px. Shared DesktopTable gains optional fixed layout/percentage widths; default auto/review behavior remains intact.

The complete authorized queue is filtered/sorted before 10/25/50 paging, preserving the server's ranked order by default. The former Expense-private controller and its tests were moved into the public shared `useDesktopTable` seam; Expense consumers migrated directly rather than re-exporting a shared primitive through a feature. Source-order, ties, counts and selection behavior are preserved.

Desktop detail presents supplied identity, vendor/requester context, exact amount, canonical category-budget projection, evidence and stock-opening items. New desktop and confirmation money preserve supplied cents; ordinary integer formatting remains the default. Category impact correctly distinguishes inventory purchases from consumed project cost, and approval copy distinguishes authorization from later disbursement. A discovered critical-classification bug was fixed in the existing canonical summary helper: non-consuming inventory-purchase amounts no longer increase projected category actual. Explicit critical/overrun flags, already-critical actuals and unknown allocation behavior remain intact; no writer or budget/margin formula changed.

Selection highlights only the row whose context is visible in the wide aside. A smaller desktop list starts/returns with empty native selection; one click opens its first row. Explicit selected identity survives narrowing/widening. Detail actions use their actual container width. Read-only roles retain source facts with disabled decision controls. Both desktop and mobile decision entry/submit callbacks use actual domain rights, pending guards and the existing opening/self-approval/override requirements.

The route no longer remounts the owner by reference-date key. Incoming source snapshots wait while a decision or pending action is active; selected facts reconcile after it closes. Locally recorded IDs prevent lagging refreshes from resurrecting a completed row until the server snapshot acknowledges removal. Header refresh is disabled while deciding. Required reason inputs have explicit accessible names, and rejection now has a visible shared Batal action. The same confirmation, reason, override, receipt, toast and writer dispatch owners remain authoritative.

Pending Change Orders use a compact desktop disclosure with exact deltas and their existing project RAB links; they are not mixed into finance/stock callbacks. Structural desktop loading follows the six-column table/detail hierarchy. Existing mobile/native composition is retained, with touched legacy count/metadata typography normalized to the documented 30px focal/10px meta roles. Pre-existing mobile amount/priority crowding at 320px remains outside this desktop redesign and is recorded in the surface brief.
