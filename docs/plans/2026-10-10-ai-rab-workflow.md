# Complete RAB workflow through AI chat

User authorized all three follow-ups: edit an existing RAB Draft, named client bundles, and approval/revision/Change Order. Preserve the established Atria grouped review rows, two-panel desktop review, single-column mobile, five-row pagination, fullDynamic money and shared confirmation/motion ownership. Model tools remain read-only; all business changes require the user review button and backend confirmation.

## Domain and operations

- Provide scoped/paginated lookup of existing RABs, client-safe lines/bundles, approved baseline, revisions and Change Orders. Require effective database permissions and Actor scope, including custom roles. Do not infer IDs, prices, client consent or evidence. Internal cost/margin/vendor/private notes stay out of model/context/client fields; budget preview is conditional on budget-read access.
- Existing Draft corrections include client title/notes, line label/description/quantity/unit/selling price, manual additions, excluding/restoring a line from the client quotation. Exclusion preserves the source/audit history. Approved, superseded and void records cannot be edited. Bundles can be created from at least two eligible same-RAB lines, corrected/hidden/restored, or dissolved while restoring member lines; never double-count children plus bundle totals.
- Initial RAB approval follows the existing direct Draft-to-Approved action, previewing its contract/budget effects. Do not invent a pending-approval stage for initial RABs. Copy an approved baseline into a new Draft revision, preserving all client lines/bundles and the original baseline. Allow explicit revision cancellation with a reason.
- Change Order creation requires same-project approved baseline and its Draft revision, reason and scope summary. Client confirmation is a separate explicit attestation with date and evidence/reference supplied by the human. Approval retains maker/checker; emergency self-approval requires the existing override permission, explicit opt-in and reason. Rejection requires a reason, keeps the approved baseline intact and permits correction/resubmission with audited history. Do not send messages or publish/sign client documents.
- Shared transactional writers serve both unchanged-signature manual actions and AI confirmation. Serialize relevant create/edit/bundle/refresh/revision/approval/Change Order paths through a consistent tenant/project/RAB lock order, recheck live state in the transaction and protect open client-confirmed Change Orders from silent content drift. Approval writes contract/budget/category derivations, matching RAP/package status, audit and existing notification outbox together; cash/inventory movements are never created by RAB actions.

## AI proposal contract

- Add strict core DTOs/schemas for bounded action inputs, client-safe snapshots, before/after review rows, total/conditional budget effect, action-specific permissions and receipts.
- Store an immutable proposal in the existing owned AI conversation path (30-day TTL). Selection/correction requests through chat create a fresh proposal; execution accepts only stored identity, never edited client mutation data. Compare a fingerprint of all relevant current records and rebuild the reviewed proposal under locks before committing. Replays return the stored receipt; stale, expired, cross-user, revoked-permission and out-of-scope proposals fail closed. Batch Draft edits are all-or-nothing.
- Register lookup/proposal tools in the typed capability catalog, and read/confirm operations in the API/web typed facades. Preserve existing create-RAB draft behavior and update guidance when an existing Draft can now be continued through chat.
- Compose one contextual action review card with shared ReviewCollection/ReviewItem/ProposalDiffRow/FormDisclosure/GroupedSurface/FactRow/MoneyValue/FormSheet. Left: exact client changes/reviewed records and details. Right: client total, conditional financial impact, readiness and explicit action. Destructive, approval and emergency decisions use a second shared ConfirmationDialog. Keep status labels concise Bahasa Indonesia, operation states stable and drafts/reading position intact across resize.
