# AI RAB draft from reviewed sources

Approved task: extend AI chat with RAB generation from selected Material RAP and Tukang/Subcon package sources, editable client descriptions and selling prices, followed by explicit human confirmation. Reuse the existing Atria review composition and manual RAB business rules.

## Contract

- Read-only tools discover permission-scoped projects and eligible, latest source rows. Material requires a locked RAP; packages require Siap/locked status. Lookup has explicit pagination and ambiguity handling. Settings/project price defaults are resolved server-side; the model receives only client-facing identity, quantity, unit and suggested selling price, without cost, margin, vendor or internal-note fields.
- A typed `RAB_DRAFT` proposal contains exact sources, their fingerprint, proposed client fields and the next RAB revision. An owned 30-day `form_draft` persists row selection and corrections. Stable source IDs and an optimistic revision protect concurrent edits. Local corrections are applied to the server draft before the separate business save.
- Shared transactional generation validates permission, tenant/project assignment, project state, eligible sources and the absence of an open RAB draft under a project lock. Manual generation retains its public signature and existing baseline-copy behavior. AI generation creates exactly the selected, reviewed client rows in the new draft revision; it does not silently copy baseline manual rows or bundles. Existing approved estimates remain intact.
- Confirmation accepts only the owned proposal identity and expected review revision. It reloads server corrections, serializes source/project checks and rejects stale fingerprints. RAB header/items, audit, completed draft and idempotent receipt commit together; double-click/retry cannot create another RAB. Saving creates a Draft and never approves, publishes, changes project budget/cash or changes inventory.

## Presentation

Reuse `ProposalCardShell`, `FormSheet`, `GroupedSurface`, grouped `FormField` controls, `MoneyInput`, `MoneyValue`, `DesktopTable`, `ChoiceRow`, `FormDisclosure` and shared footer/motion/dismissal behavior. Card shows project, selected row count, selling total and Review. Desktop has a client-line table and concise summary/action aside; mobile has divided material/package rows and a grouped editor for the chosen row. Five rows per page on every viewport. Client fields are distinct from source metadata; selection and corrections survive pagination, reload and resize. Dirty corrections prevent Save and use the existing dismissal guard. Completed state links to the project RAB.
