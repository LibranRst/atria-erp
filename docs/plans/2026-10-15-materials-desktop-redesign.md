# Material desktop redesign

## Approved direction

Extend the accepted Dashboard, Expenses, Approvals and Reconciliation desktop grammar into canonical `/materials`, covering Ringkasan, Stok, Kebutuhan and Aktivitas. Inherit Atria Operate: cool canvas, Manrope, compact white grouped owners, native shared HeroUI tables, capsule controls, semantic ink/terracotta and restrained shared motion. This is the user's specified continuation of the current system, not a new visual identity or open concept exercise.

Use one compact financial/operational summary band, peer views and contextual controls. Stock and need tables support comparison without summing incompatible units. Activity distinguishes movements, goods receipts, transfers and stock counts. At >=1280px actual row context may sit in an independent 18rem aside; 1024–1279px progresses list/detail with Back. A hidden aside never creates an active fallback selection. Empty results fill the available width. Existing mobile and native-pinned composition remains authoritative.

## Domain, data and ownership

Preserve the stable MaterialsControlCenter and current operation hook as owners of drafts, selection, pending work, confirmation, receipt inspection and shared sheets. Receipt is physical evidence distinct from payment; reservation/use do not silently create cash. Stock movement/audit, independent approval, reversal, count and emergency-override rules remain with existing writers and permissions.

Inspect complete versus preview collections before pagination. Inventory and shortages currently provide complete collections; activity previews have different limits. Use complete collections for local full-result table sorting/filtering/pagination and add a bounded server desktop activity read where necessary. Use 10/25/50 pagination with accurate totals. Do not paginate a capped preview as a full queue. Keep shortage permission/source failure distinct from valid empty or zero. Read initial and desktop data within tenant and appropriate project scope. Do not reset/seed development data or perform real stock/financial mutations during QA.
