# Desktop finance workflow consistency audit

## Scope

Audit the existing canonical desktop Pengeluaran → Persetujuan → Rekonsiliasi flow in the live development app, preserving Atria's established Dashboard grammar and mobile/native composition. Cover field expenses, vendor bills and planned payments; the complete approval queue; unmatched bank/cash entries and reconciliation history.

Inspect compact hierarchy, table/toolbar/footer consistency, optional row selection, list/detail at 1024–1279px and independent context at ≥1280px, query/filter/sort/page retention, complete/empty/error/loading states, keyboard/focus, nested overlays, dirty/pending guards and source freshness. Reuse public shared UI. Fix verified problems, without speculative redesign or a second infrastructure owner.

## Execution

1. Graft/code review of each module in parallel; one live browser owner performs a bounded batched inspection of all three routes.
2. Record concrete defects with evidence, severity and an owning file before edits; fix them in one coordinated batch.
3. Add focused behavioral regression coverage for substantive fixes. Verify real read/navigation/overlay interactions on the dev app; exercise write success/failure and authorization scenarios with mocks or disposable test fixtures only.
4. Confirm desktop 1024/1280/1440 and mobile 320/360/390/430 plus native fallback, selection/dirty state across resize and shared nested dropdown focus/dismissal. Use existing representative datasets; do not reset, seed or mutate the development database and do not execute financial decisions/transfers/matches in the live browser.
5. Run relevant tests, workspace typechecks/lint/format, build and token/style checks as appropriate. Update surface guidance only for changed contracts; record final audit findings/evidence and refresh Graft after substantial source changes.

## Safety and ownership

Finance permissions, server project/tenant scope, budget and cash semantics, audit logs and reconciled immutability remain authoritative. No new bulk workflow, automatic approval/payment/matching, backend query or financial writer is planned. The shared `DesktopTable`, `DesktopTablePagination`, `SegmentedTabs`, filters, `MoneyValue`, status/fact surfaces and existing overlay owners remain the baseline.
