# design-sync NOTES

Atria ERP is a private Next.js app (no publishable package, no Storybook prior to this sync). This file records the repo-specific fixes so future syncs don't have to rediscover them.

## Repo shape

- No `main`/`module`/`exports`/`types` in the real `package.json` — added Storybook (`@storybook/nextjs`, webpack5) from scratch under `.storybook/`, plus `.design-sync/entry.ts` as a synthetic package entry re-exporting the design-system surface (`components/ui/**`'s public barrel, `components/layout/**`'s prop-driven shell parts, and a few real components not in the `ui` barrel: `FactRow`, `PanelSection`, `SheetSection`, `MoneyValue`, `MoneyMetricPill`).
- `findTypesRoot`/`exportedNames` (storybook shape's export-list source) need a real `.d.ts` tree reachable from `pkgJson.types`/`publishConfig.types`. Fixed by generating one via `bunx tsc -p .design-sync/tsconfig.dts.json` (declaration-only build of `.design-sync/entry.ts`) into `.design-sync/dts-out/`, and pointing `package.json`'s `publishConfig.types` at the generated entry. `cfg.buildCmd` re-runs this on future syncs.
- `.design-sync/tsconfig.dts.json` (`include: ["entry.ts"]` only — don't broaden it; a broader glob (e.g. `lib/**`) pulls in unrelated files like `lib/auth-client.ts` whose `better-auth` inferred type isn't portable, and errors that block nothing but add noise). Entry re-exports **must use relative paths**, not the `@/` tsconfig alias — the converter's own ts-morph `Project` (in `lib/dts.mjs`) has no `paths` mapping, so a `@/`-aliased `export * from` at the entry can't be resolved and yields 0 exported names.

## `[GENERAL]` fixes (apply to every re-sync)

- **`--font-inter`/`--font-jetbrains` must be set on `document.documentElement`, not a nested wrapper div.** The real app sets these via `className` on `<html>` (`app/layout.tsx`). `--font-sans` (`app/globals.css`) references `var(--font-inter)`; a custom property whose `var()` reference fails to resolve AT ITS POINT OF DECLARATION becomes permanently invalid for every inheriting descendant, even if a deeper element later defines the variable it depends on. `.storybook/preview.tsx`'s `RootFontClassSetter` sets the classes on `documentElement` via `useEffect` to match.
- **Storybook's production build (`storybook build`, used for the design-sync reference) needs `MiniCssExtractPlugin`, not the default `style-loader`.** The converter's CSS fallback (`css-fallback.mjs`) only scrapes a `<link rel="stylesheet">` from `iframe.html` — style-loader's injected `<style>` tags never produce one. `.storybook/main.ts`'s `webpackFinal` swaps the loader only when `configType === "PRODUCTION"` (dev keeps style-loader for HMR speed).
- **`next/link`'s bundled code throws `ReferenceError: process is not defined` in a real browser.** It reads `process.env.__NEXT_*` build-time flags that Next's own build normally replaces; esbuild's `define` only covers the one `process.env.NODE_ENV` key we set. Can't fork `bundle.mjs` (forbidden) to widen the define, so `cfg.extraEntries` injects `.design-sync/polyfills/process-shim.ts` (sets `globalThis.process = { env: {} }` if unset) — it's listed first so its side effect runs before anything else in `_ds_bundle.js`, and every preview loads after the main bundle so it inherits the polyfill too.
- **Never wrap every story in `ActivityDetailProvider`.** It unconditionally renders the real `ActivityDetailSheet`, which imports a real Server Action (`getActivityDetail`) that reaches `lib/auth.ts` (server-side Better Auth config with a live DB adapter). In `storybook build`'s production mode this throws `BETTER_AUTH_SECRET wajib dikonfigurasi pada environment production.` for literally every story. None of the synced components use `useActivityDetail`, so `.storybook/preview.tsx`'s global decorator only wraps `ProjectStateProvider` now.
- **Two independent timing races, same root cause: React 19's scheduler commits the initial render a tick or two after Playwright's `networkidle` fires on this machine.** Evaluating DOM state immediately after `page.goto(..., { waitUntil: 'networkidle' })` can see an empty root — confirmed by direct repro (immediate eval → empty; +400ms → full correct content). Heavier grids (e.g. an icon gallery rendering ~75 icons) hit this far more often than a 2-3-cell story. Patched with a local-only `page.waitForTimeout(400)`:
  - `.ds-sync/package-validate.mjs`'s render-check, right after its per-component `page.goto`.
  - `.ds-sync/storybook/compare.mjs`, right after the DS-page `page.goto` and before the `__dsCells`/cell-discovery `page.evaluate`.
  - `.ds-sync/storybook/compare.mjs`'s `storyShot()` (the per-story `?story=` capture used by every `cardMode:"single"` portal/overlay component), right after `settleRender(dsPage)` — found via `BottomNavBackdrop` grading (fan-out batch 1): its `AnimatePresence` fade-in (`initial={{opacity:0}}` → `animate={{opacity:1}}`, 0.35s) was reliably caught mid-transition, rendering as "no backdrop at all" vs storybook's fully-visible scrim. Every `cardMode:"single"` component (`OperationalFormSheet`, `WorkflowFormSheet`, `HeaderMorphMenu`, `BottomSheet`, `BottomNavBackdrop`) is equally exposed — re-check those if this patch is ever missing.
    Neither fix is part of the upstream skill scripts — `.ds-sync/` is regenerated fresh from the packaged skill on every sync, so **re-apply all three `waitForTimeout(400)` patches after re-staging** until/unless the upstream harness adds its own settle wait.

## Component-specific exclusions

- **`BottomNav`** — imports `ROLE_ID_TO_NAME` from `lib/auth/permissions.ts`, which also imports the real Drizzle DB client (`@/db`) at module scope. Bundling it pulled in `@neondatabase/serverless` + `drizzle-orm` (12 inlined packages, 7.8MB bundle) and, since all components share one IIFE, a bundle-eval-time reference in that chain broke `window.AtriaUI` for every component, not just BottomNav. Excluded from `.design-sync/entry.ts`; its prop-driven subparts (`BottomTabBar`, `QuickActionFab`, `BottomNavBackdrop`, all in `bottom-nav-parts.tsx`) have no such coupling and are synced normally. The Storybook story for `BottomNav` (`components/layout/bottom-nav.stories.tsx`) is left in place for local dev preview; design-sync just drops it via `[TITLE_UNMAPPED]`.
- **`MobileShell`** — renders `GlobalExpenseDrawer`/`GlobalVendorBillDrawer`/`GlobalProjectDrawer`/`GlobalInvoiceDrawer`, each of which imports a real Server Action module (`app/actions/**`) with Node-only transitive imports (`crypto`, Next's `@opentelemetry/api` tracer) that esbuild can't bundle for `platform: 'browser'` at all (hard build error, not just bloat). Same exclusion rationale as BottomNav, one level more severe. Its Storybook story is also kept for local dev preview only.

## `cfg.overrides` (portal/overlay components — `cardMode: "single"`)

`OperationalFormSheet`, `WorkflowFormSheet`, `BottomNavBackdrop`, `HeaderMorphMenu`, `BottomSheet` all use `createPortal`/`fixed` positioning that a grid card can't contain (`[GRID_OVERFLOW]`). All five are configured with `cardMode: "single"` in `.design-sync/config.json`.

## Re-sync risks

- The three timing patches above are the single biggest re-sync risk — they live in `.ds-sync/` (gitignored, regenerated per sync) and will need re-applying, or every render-check/compare run will show false `[RENDER]`/`unpaired` failures again on this machine. The wait duration is itself load-dependent: 400ms was enough in isolation, but `package-validate.mjs`'s render-check needed bumping to 900ms after a large fan-out grading run left the machine under heavier load (even then, one run still showed 6/59 false failures that a bare retry cleared). If a final validate run shows `[RENDER]` failures on components already graded `match` by compare.mjs, retry before treating it as real — it's this same race, not a regression.
- `unpaired` verdicts ("no cell labeled X — the .tsx export for this story is missing or renamed") are not always a real pairing defect on this machine — several showed up during fan-out grading purely because a prior session's compare run was interrupted mid-capture (a hit session/API rate limit killed 4 parallel grading subagents at once). In every one of those cases the generated preview wrapper and compiled bundle were already correct, and a bare `compare.mjs --components <Name>` re-run with zero code changes produced a clean pairing. Before diagnosing an `unpaired` verdict as a real `.tsx`-authoring problem, recapture once — it may just be a stale/interrupted capture from an earlier run.
- `Button`'s story file has 14 stories; the converter's default `--max-stories 6` cap means `WithIcons`, `Pending`, `Disabled`, `FullWidth`, `AsLink`, `Icon`, `SectionActionDefault`, `SectionActionTextOnly` were never individually graded via compare.mjs (though all were spot-checked visually in-browser during the Storybook bootstrap phase, and `Button`'s primary story graded a clean `match`). Raise `--max-stories 14` for `Button` on a future sync if those tail variants need individual verification.
- The `publishConfig.types` field in `package.json` and the `.design-sync/dts-out/` directory it points to only exist after running `cfg.buildCmd`. A sync that skips that step will see `exportedNames()` fall back to 0 exports and every storybook title reported `[TITLE_UNMAPPED]`.
